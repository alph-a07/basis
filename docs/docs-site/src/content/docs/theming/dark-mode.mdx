Basis follows the system dark setting by default. Pin it or let users choose.

## 1. Primary Mechanism: `useDarkTheme`

The `useDarkTheme` parameter on `BasisTheme` selects which resolved token tree is injected into `LocalBasisTheme`. By default it reads `isSystemInDarkTheme()`, adapting automatically to Android device settings:

<DocSnippet name="support_dark_mode" />

### Resolution Targets vs. Runtime Presentation

- **`ControlIntent.mode`** (`ModeControl`): Configured during intent creation. Defines which mode token trees the resolver generates — by default both `ThemeMode.Light` and `ThemeMode.Dark`.
- **`useDarkTheme`**: Configured at runtime in Compose. Selects which resolved tree is actively presented to the user.

## 3. Surface Lightness Steps

Shadows are hard to see on dark backgrounds, so dark surfaces step up in lightness instead. Basis assigns distinct OKLCH luminance levels per surface role:

| Surface Token | Light Mode (L) | Dark Mode (L) | Role |
| :--- | :--- | :--- | :--- |
| **`BasisTheme.colors.surface.recessed`** | `0.94` | `0.12` | Sunken backgrounds, scroll troughs, search fields. |
| **`BasisTheme.colors.surface.default`** | `0.98` | `0.16` | Main screen canvas, window backgrounds. |
| **`BasisTheme.colors.surface.elevated`** | `1.00` | `0.22` | Cards, dialogs, bottom sheets. |
| **`BasisTheme.colors.surface.inverse`** | `0.18` | `0.92` | High-inversion containers, snackbars, toasts. |

## 4. Focus and Selection Contrast

Focus ring contrast of ≥ 3:1 against surface and canvas is checked during resolution. Selection tints use lightness offsets that preserve body text legibility (≥ 4.5:1).

## Verify the Result

Toggle dark mode in your Android emulator (or set `useDarkTheme = true`).

You should see your screen canvas transition to `L = 0.16` and cards to `L = 0.22`, providing distinct visual elevation without drop shadows.
